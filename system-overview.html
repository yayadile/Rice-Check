RiceCheck

Aplikasi Android untuk memeriksa kualitas beras dari sebuah foto, lalu membandingkannya dengan harga per kilogram. Vonis tidak ditebak dari citra, melainkan dihitung dari ketidakcocokan harga vs kualitas. Seluruh analisis berjalan on-device dan offline — tanpa login, sinkronisasi, maupun izin internet.

📖Pendahuluan

Dokumen ini menjelaskan cara kerja sistem RiceCheck secara menyeluruh — mulai dari konsep produk, aturan vonis, arsitektur perangkat lunak, pipeline machine learning on-device, layer data, hingga pengujian dan proses build. Penjelasan disusun mengacu langsung pada kode di app/src/main/kotlin/com/yayadile/ricecheck/ dan dokumentasi di folder docs/.

Prinsip utama Model ML bukan pendeteksi oplosan. Model hanya menghasilkan metrik kualitas. Vonis oplosan dihitung oleh logika domain murni (VerdictCalculator) dari hubungan harga dan kualitas. Pemisahan ini sengaja dibuat agar hasil dapat diaudit dan diuji tanpa model.

1Konsep & Tujuan

RiceCheck tidak berusaha mendeteksi beras palsu langsung dari gambar. Yang diukur adalah kualitas beras (skor 0–100, persentase butir utuh, persentase menir/patah, dan indikasi pemutih). Setelah itu, hasil kualitas dibandingkan dengan harga per kg yang dimasukkan pengguna:

  • Harga mahal tetapi kualitas rendah → BERPOTENSI OPLOSAN
  • Harga mahal dan kualitas tinggi → ASLI
  • Harga murah atau harga tidak diisi → LAPORAN KUALITAS (tanpa vonis)

Fokus v1 adalah satu loop: onboarding → beranda → kamera (foto + harga) → analyzing → hasil → riwayat. Fitur di luar itu (login, sinkronisasi, statistik pola, share) sengaja ditunda.

📷 Input

Foto beras (kamera atau galeri) + harga per kg (opsional).

🧠 Analisis

YOLO mendeteksi butir, SVM menilai pemutih, lalu mapping menghitung metrik.

⚖️ Vonis

Logika murni membandingkan harga vs kualitas. Bukan dari model.

2Rule Vonis: Harga vs Kualitas

Semua ambang batas disimpan di satu tempat: domain/VerdictConfig.kt. Tidak ada file lain yang boleh menulis angka 14_000 atau 60 secara langsung. 

object VerdictConfig {
    const val PREMIUM_PRICE = 14_000   // Rp/kg
    const val LOW_QUALITY   = 60       // skor < 60 = rendah
}
Harga per kgKualitas (skor)Hasil vonisWarna UI
≥ Rp14.000 (premium)< 60 (rendah)BERPOTENSI_OPLOSANmerah
≥ Rp14.000 (premium)≥ 60 (tinggi)ASLIhijau
< Rp14.000 (murah)apa punLAPORAN_KUALITASnetral
tidak diisi (null)apa punLAPORAN_KUALITASnetral

Implementasi sebagai fungsi murni (pure function) di domain/VerdictCalculator.kt:

fun decide(price: Int?, q: QualityReport): String = when {
    price == null -> LAPORAN_KUALITAS
    price >= VerdictConfig.PREMIUM_PRICE && q.qualityScore < VerdictConfig.LOW_QUALITY
        -> BERPOTENSI_OPLOSAN
    price >= VerdictConfig.PREMIUM_PRICE -> ASLI
    else -> LAPORAN_KUALITAS   // harga murah: laporan saja, tanpa vonis
}
Batas bersifat inklusif Harga tepat Rp14.000 sudah dianggap premium. Skor tepat 60 sudah dianggap kualitas tinggi. Skor 59 dengan harga Rp14.000 → oplosan.

4Alur Satu Siklus Scan

Perjalanan lengkap satu pemindaian, langkah demi langkah:

1. Beranda — tap "Scan Beras"
2. Camera — izin CAMERA, preview CameraX, frame guide, isi harga (opsional)
shutter → ImageCapture (targetRotation dari display, JPEG tegak) → filesDir/scans/<timestamp>.jpg
3. Navigasi analyzing?photoUri=…&price=…
4. AnalyzingViewModel → ScanRepository.save(photoPath, price) decode + EXIF → RiceClassifier.classify() → VerdictCalculator.decide() → insert Room
kembalikan scanId
5. Navigasi result/{scanId} (Camera & Analyzing di-pop dari back stack)
6. Result membaca row via observeById(scanId), menampilkan 3 state + breakdown

Detail repositori: orkestrasi inti

Inilah "jantung" sistem — ScanRepositoryImpl.save() menyatukan foto, model, dan logika vonis lalu menuliskannya ke Room: 

override suspend fun save(photoPath: String, price: Int?): Long = withContext(ioDispatcher) {
    // 1. Decode dibatasi ~1920px: YOLO butuh 1280, SVM butuh 256 (cegah OOM di foto 48 MP)
    val bitmap = ImageDecoder.decode(photoPath, targetSizePx = MAX_DECODE_SIZE)
        ?: throw IOException("Foto tidak bisa dibaca: $photoPath")

    // 2. Model ML → QualityReport (metrik kualitas, bukan vonis)
    val report = classifier.classify(bitmap)

    // 3. Domain murni → vonis dari harga vs kualitas
    val verdict = VerdictCalculator.decide(price, report)

    // 4. Persistensi
    dao.insert(ScanResultEntity(
        photoPath = photoPath, price = price, result = verdict,
        qualityScore = report.qualityScore, wholeGrainPct = report.wholeGrainPct,
        brokenPct = report.brokenPct, bleachLevel = report.bleachLevel.name,
        createdAt = System.currentTimeMillis()
    ))
}
Tidak ada angka palsu Bila model tidak tersedia, foto tidak terbaca, atau tidak ada butir yang terdeteksi, sistem melempar AnalysisException dan UI menampilkan layar gagal. Aplikasi tidak pernah mengarang angka. Hanya saat model benar-benar gagal dimuat, banner peringatan "Model belum tersedia…" ditampilkan.

Membatalkan analisis

Saat pengguna menekan "Batal" di layar Analyzing, job dibatalkan dan file foto sementara dihapus. Karena tidak ada baris DB yang ditulis sebelum save() selesai, tidak ada data setengah jadi yang tertinggal.

5.1 Detektor Butir — YOLO11s (LiteRT)

Wrapper LiteRT ada di ml/YoloDetector.kt, sedangkan prapemrosesan/pascapemrosesan murni (tanpa dependensi Android) ada di ml/YoloPost.kt sehingga bisa diuji sebagai unit test.

Output NCHW 1×9×33600 (4 box + 5 kelas)
Kelas 0 utuh · 1 patah · 2 menir · 3 gabah · 4 batu

Prapemrosesan (letterbox)

Gambar di-resize bilinear dengan mempertahankan rasio, lalu diberi padding warna abu (114) agar pas 1280×1280. Padding dihitung setengah selisih ukuran. 

fun letterbox(srcW: Int, srcH: Int, size: Int = IMG_SIZE): Letterbox {
    val scale = min(size.toDouble() / srcW, size.toDouble() / srcH).toFloat()
    val newW = max((srcW * scale).roundToInt(), 1)
    val newH = max((srcH * scale).roundToInt(), 1)
    val padX = ((size - newW) / 2.0 - 0.1).roundToInt()
    val padY = ((size - newH) / 2.0 - 0.1).roundToInt()
    return Letterbox(scale, padX, padY, newW, newH)
}

Dekode & NMS

Output mentah berisi banyak kandidat (anchors). Untuk setiap anchor diambil kelas dengan skor tertinggi; jika melewati ambang, box dikonversi dari pusat+lebar+tinggi menjadi koordinat (x1,y1,x2,y2). Selanjutnya Non-Maximum Suppression per kelas membuang box yang saling tumpang tindih. Box dikembalikan ke koordinat piksel foto asli.

5.2 Ekstraksi Fitur — GLCM + HOG + Histogram Warna

Jalur SVM memakai citra BGR 256×256. ml/FeatureExtractor.kt adalah port Kotlin identik dengan pipeline pelatihan (scikit-image / OpenCV), menghasilkan 8202 fitur per gambar.

Grup fiturJumlahDetail
GLCM6contrast, dissimilarity, homogeneity, energy, correlation, ASM — jarak 1, 4 arah, 256 level
HOG81009 orientasi, sel 16×16, blok 2×2, normalisasi L2-Hys
Histogram warna9632 bin × 3 kanal BGR, dinormalkan L2
Total8202urutan: GLCM → HOG → histogram

Segmentasi citra (Otsu + morfologi)

Citra dikonversi ke grayscale memakai koefisien fixed-point OpenCV 5.0, lalu disegmentasi dengan ambang Otsu. Operasi morfologi menyingkirkan noise: OPEN (3×3) kemudian CLOSE (kernel 5×5, karena iterasi menumbuhkan kernel). 

// OpenCV 5.0 cvtColor BGR2GRAY fixed point
gray[i] = ((r * 9798 + g * 19235 + b * 3735 + (1 shl 14)) shr 15)

// skimage graycomatrix(symmetric=True) = P + Pᵀ → diagonal digandakan
p[i,j] = original[i,j] + original[j,i]
Catatan porting penting
  • OpenCV 5.0 BGR2GRAY memakai koefisien 15-bit di atas (bukan varian 14-bit lama).
  • graycomatrix(symmetric=True) = P + Pᵀ, sehingga entri diagonal digandakan.
  • MORPH_CLOSE, iterations=2 = satu kernel 5×5, bukan dua kali 3×3.
  • HOG skimage 256×256 / sel 16 / blok 2×2 → 8100; bin memakai sudut terdekat (tanpa interpolasi).

5.3 Klasifikasi Pemutih — SVM Linear

Model SVM (scikit-learn SVC(kernel="linear"), C=10) diekspor ke format biner custom dan dibaca murni oleh Kotlin di ml/BleachClassifier.kt. Varian linear non-CLAHE ini memiliki akurasi 94% dan F1 0.9388, dengan 156 support vector. Classifier juga mendukung kernel RBF (lewat field kernel pada aset), tetapi yang dibundel saat ini adalah linear.

Format aset biner RSVM (versi 2)

Little-endian float32 dengan tata letak:

  • Magic RSVM, versi, jumlah fitur, jumlah support vector, jumlah kelas, kernel (0 = rbf, 1 = linear)
  • gamma (tidak dipakai untuk linear, ditulis 0) dan bias
  • scaler mean[] dan scaler scale[] (untuk StandardScaler)
  • support vectors[156 × 8202] (float32)
  • dual coefficients[156] (float32)

Perhitungan keputusan

Fitur terlebih dahulu distandardisasi. Untuk kernel linear, bobot w = Σ dual_i · sv_i di-precompute sekali saat aset dimuat, sehingga keputusan cukup satu dot product (jauh lebih murah daripada mengevaluasi 156 kernel). Nilai positif berarti kelas 1 (pemutih): 

// z = (x − mean) / scale
val z = FloatArray(nFeatures) { (features[it] - mean[it]) / scale[it] }

// linearWeights[f] = Σ dual_i · sv_i[f]  (dihitung sekali di constructor)
var sum = 0.0
for (f in 0 until nFeatures) sum += linearWeights[f] * z[f]

val isPemutih = (sum + bias) > 0f

Skor keyakinan (bleachPct)

Nilai keputusan SVM adalah margin bertanda, bukan probabilitas terkalibrasi. Untuk ditampilkan di UI, margin dipetakan lewat sigmoid stabil menjadi skor 0–100 oleh BleachClassifier.pemutihConfidence(). Ini keyakinan model, bukan kadar kimia pemutih.

Kelas 0 normal · 1 pemutih
Dimensi fitur 8202
Support vectors 156
Kernel linear non-CLAHE

5.4 Mapping Metrik Kualitas

Hasil hitungan butir per kelas diubah menjadi metrik yang tampil di UI memakai rumus yang telah disetujui di ml/QualityMapping.kt. Perhatikan: qualityScore memperhitungkan gabah dan batu sebagai pengurang, sedangkan persentase utuh/patah hanya memperhitungkan kelompok beras (utuh + patah + menir).

Definisi kelompok:

  • grain = utuh + patah + menir (kelompok beras)
  • total = grain + gabah + batu (seluruh butir terdeteksi)
wholeGrainPct = round(100 · utuh / grain)
brokenPct     = round(100 · (patah + menir) / grain)
qualityScore  = round(100 · utuh / total)

Implementasi:

val grain = whole + broken + menir
val total = grain + gabah + batu
wholePct = if (grain > 0) (100.0 * whole / grain).roundToInt() else 0
brokenPct = if (grain > 0) (100.0 * (broken + menir) / grain).roundToInt() else 0
score = if (total > 0) (100.0 * whole / total).roundToInt() else 0

Output akhirnya dibungkus menjadi QualityReport:

data class QualityReport(
    val qualityScore: Int,      // 0..100
    val wholeGrainPct: Int,     // % butir utuh
    val brokenPct: Int,         // % menir/patah
    val bleachLevel: BleachLevel, // RENDAH / TINGGI
    val bleachPct: Int,         // 0..100 keyakinan model (bukan kadar kimia)
    val isStub: Boolean = false   // penanda model placeholder
)

Penyimpanan Foto

Foto disimpan di internal storage pada filesDir/scans/<timestamp>.jpg. Database hanya menyimpan path. Saat pengguna menghapus riwayat, repository menghapus baris DB sekaligus file fisik — logikanya ada di repository, bukan di UI.

ScanFileStore.importFromUri() menyalin foto hasil pilih galeri ke internal storage agar scan memiliki salinan foto miliknya sendiri (galeri memakai Android Photo Picker PickVisualMedia, jadi tidak perlu izin storage).

Decoding gambar (EXIF + sampling)

util/ImageDecoder.kt menjadi jalur decode tunggal agar model dan UI melihat orientasi yang sama. BitmapFactory mengabaikan orientasi, jadi rotasi EXIF diterapkan manual. Ukuran dibatasi (inSampleSize) maksimal ±1920px saat decode untuk scan, sehingga foto kamera 48 MP tidak menyebabkan OOM.

10Dependency Injection

Tidak memakai Hilt. DI manual melalui AppContainer yang dibuat sekali di RiceCheckApplication dan diteruskan ke Compose lewat LocalAppContainer (sebuah staticCompositionLocalOf). 

class AppContainer(context: Context) {
    val database by lazy { Room.databaseBuilder(...).addMigrations(AppDatabase.MIGRATION_1_2).build() }
    val scanDao by lazy { database.scanDao() }
    val riceClassifier by lazy { RiceClassifier(appContext) }
    val scanFileStore by lazy { ScanFileStore(appContext) }
    val scanRepository by lazy { ScanRepositoryImpl(scanDao, riceClassifier) }

}

  • Release: isMinifyEnabled = true, isShrinkResources = true
  • room.schemaLocation di-set via KSP untuk ekspor skema
Tanpa izin INTERNET Manifest hanya meminta android.permission.CAMERA. Tidak ada INTERNET, sehingga aplikasi benar-benar offline penuh.

14Model & Lisensi

Asal usul model

  • YOLO11s — dilatih Ultralytics pada dataset dataset_det_v3, epochs 150, batch 2, imgsz 1280. Diekspor ke ONNX (1×3×1280×1280 → 1×9×33600) lalu dikonversi ke TFLite.
  • Bleach SVM — scikit-learn SVC(kernel="linear"), C=10, probability=True; varian non-CLAHE terbaik (akurasi 94%, F1 0.9388, 156 support vector). Diekspor ke format biner custom RSVM (versi 2, menyimpan jenis kernel).

Regenerasi & verifikasi

Skrip Python di tools/ menghasilkan aset runtime dan vektor golden:

# 1. ONNX kanonik dari bobot terlatih
yolo export model=models/yolo11s_beras/best.pt format=onnx imgsz=1280 opset=12 simplify=True

# 2. ONNX → TFLite
onnx2tf -i models/yolo11s_beras/best.onnx -o build/model_export/yolo -osd -coion

# 3. Cek numerik TFLite vs ONNX
python tools/verify_tflite.py --onnx models/yolo11s_beras/best.onnx \
  --tflite build/model_export/yolo/best_float32.tflite --image <photo.jpg>

# 4. Aset SVM + golden vectors
python tools/export_svm_asset.py
python tools/verify_svm_asset.py
python tools/make_svm_golden.py
python tools/make_yolo_golden.py
⚠️ Lisensi AGPL-3.0 Bobot YOLO11s berasal dari Ultralytics dan berlisensi AGPL-3.0. Distribusi aplikasi dengan aset ini memiliki implikasi AGPL yang harus diverifikasi sebelum rilis.

15Batasan & Post-v1

Batasan yang diketahui

  • Hasil adalah estimasi, bukan uji laboratorium.
  • Kode preview saat ini ikut ter-kompilasi ke build release.
  • Belum ada build AAB; signing release bergantung pada keystore lokal.
  • Uji on-device membutuhkan emulator dengan -gpu host (SwiftShader bermasalah di sebagian mesin).
  • Ukuran APK besar (±70 MB release) karena menyertakan LiteRT + model; APK bersifat universal (semua ABI).

Di luar scope v1 (ditunda)

  • Login & sinkronisasi antar-perangkat
  • Statistik pola (merek/toko sering oplosan)
  • Berbagi hasil scan
  • Dark mode & dynamic color
  • Multi-bahasa
  • Toggle Asli/Oplosan buatan (itu bukan fitur)
Aturan data jujur Semua angka di UI harus berasal dari Room atau model. Tidak boleh ada data palsu yang ditampilkan sebagai data nyata. Jika model gagal, tampilkan kegagalan — bukan angka karangan. Klaim "akurat" atau "murni 100%" dilarang karena tidak berbukti.
